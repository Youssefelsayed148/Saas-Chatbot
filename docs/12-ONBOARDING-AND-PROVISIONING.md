# One provisioning service
Two entry points: self-service and admin-managed. Both invoke `ProvisioningService.request(...)` with authenticated actor, target tenant, requested bot configuration, source and idempotency key. A shared service validates inputs, creates/reuses tenant/bot, records request and audit, and schedules optional ingestion. Staff path changes actor authorization and invitation workflow, not core provisioning logic.
State: requested → validating → provisioning → ready; or failed with retry, cancelled. Durable request record; uniqueness on actor/tenant/idempotency key and payload hash; concurrent retries cannot duplicate bot. No cross-product SKU branching for MVP. P1 implements plain tenant/bot CRUD; the shared ProvisioningService (self-service + staff, with data upload) is built in P5-03. Never require website URL to create a draft bot.
