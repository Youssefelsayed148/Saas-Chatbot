# One provisioning service

Two entry points: self-service and admin-managed. Both invoke the same `ProvisioningService` with an authenticated actor, requested tenant/bot configuration, and an idempotency key. The service creates or reuses tenant/bot resources, records the request and audit event, and can schedule optional ingestion. The staff path changes actor authorization and the account workflow, not the core provisioning logic.

Self-service signup (P7-03) exists but is CLOSED by default: `POST /api/v1/provisioning/self-service` requires an authenticated, CSRF-checked user and — when `self_serve_signup` is enabled — creates one Free PLACEHOLDER tenant, direct admin membership, and first draft bot. A deterministic per-account idempotency key lets concurrent retries return the same tenant and bot; a changed payload on that key returns 409. With the flag off (the committed default) the route refuses, `POST /api/v1/auth/register` requires a valid invitation (`403 INVITATION_REQUIRED`) and the login screen shows no Register link. The `/register` page still tells visitors that registration is by invitation only when the flag is off. No email provider is configured in either path.

Staff onboarding (the built default, S1–S3 of the account/administration slice) no longer uses a single onboarding form: the platform operator creates the organization, creates the user (staff-set or generated password, shown once), assigns the membership, creates the bot, then uploads knowledge through the bot's Knowledge tab, ingests, publishes and installs the widget. The old `POST /api/v1/platform/onboarding` route was retired in S3; the durable `ProvisioningService` remains in the codebase and is exercised by the flagged-on self-service path and by regression tests (historical GET status and CSV routes remain). Neither path requires a website URL.

State: requested → provisioning → ready; or failed. Durable request record; unique `(mode, idempotency_key)` plus payload hash; concurrent retries cannot duplicate a tenant/bot. No cross-product SKU branching for MVP.
