# Proposed PostgreSQL model (design, not migrated)
## Foundation tables
`users(id UUID PK,email CITEXT UNIQUE,password_hash,verified_at,created_at)`; `tenants(id,name,slug UNIQUE,status,created_at)`; `memberships(tenant_id,user_id,role,status, UNIQUE(tenant_id,user_id))`; `bots(id,tenant_id,name,status,config_json,published_revision_id NULL,created_at,updated_at, UNIQUE(tenant_id,id))` — `config_json` holds assistant/business name, description, welcome message EN/AR, opening questions, default language, support email/phone, colour/position, handoff toggle, allowed domains (validated by a Pydantic schema); `audit_events(id,tenant_id NULL,actor_user_id NULL,action,target_type,target_id,metadata_json,created_at)`.
## Subsequent tables
`provisioning_requests(id,tenant_id,actor_id,mode,status,idempotency_key,payload_hash,error,created_at)`; `jobs(id,tenant_id,bot_id,type,status,attempts,run_after,lease_until,payload_json,error)`; `sources(id,tenant_id,bot_id,source_type file|qa_csv,filename,status,config_json)`; `documents(id,tenant_id,bot_id,source_id,title,source_url NULL,language,page_type NULL,content_hash)`; `knowledge_revisions(id,tenant_id,bot_id,status,published_at)`; `chunks(id,tenant_id,bot_id,revision_id,document_id,title,heading,text,text_norm,language,priority,content_hash,fts_en tsvector GENERATED,fts_simple tsvector GENERATED, GIN indexes; composite FK (tenant_id,bot_id) → bots)` (no vector column in MVP; optional nullable `embedding` added by a later migration, docs/14 §1); `visitor_sessions(id,tenant_id,bot_id,expires_at)`; `conversations(id,tenant_id,bot_id,session_id)`; `messages(id,tenant_id,conversation_id,role,text,can_answer,needs_human,response_ms,created_at)`; `citations(id,tenant_id,message_id,document_id,url,excerpt)`; `message_feedback(id,tenant_id,message_id,rating,created_at, UNIQUE(message_id))`; `usage_events(id,tenant_id,bot_id,kind,units,created_at)`; `leads(id,tenant_id,bot_id,consent_at,contact_json)`.
## Constraints
Use UUIDs, FK constraints and explicit indexes `(tenant_id, bot_id)`; composite FKs where appropriate. Never accept tenant_id from public widget as authority; resolve through opaque bot locator. Full-text search columns are generated and GIN-indexed (docs/14 §5). Vector dimension is decided only if/when the semantic upgrade is approved. Index and publication design must ensure published-only retrieval. Password hashing via vetted library; no plaintext secrets in DB. Use Alembic migrations, not startup `create_all`.
## Transactions
Bot create + audit in one transaction; onboarding resource creation idempotent; job claim atomic; knowledge publication atomically swaps bot's published revision pointer; metering designed for retries and deduplication.
