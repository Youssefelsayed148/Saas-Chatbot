# Widget contract
One copy/paste script snippet with public locator, rendered in sandboxed iframe. Settings: theme color, avatar/name, greeting, placement, language/RTL, visibility, allowed domains. Widget fetches only public bot config; visitor gets short-lived scoped session capability; conversation messages checked for bot/session ownership. Browser Origin is a defense signal, not sufficient authentication. Include rate limits and abuse controls.
States: loading, ready, typing, answer/citations, no knowledge, paused, quota exceeded, network error, reconnect. Mobile responsive, keyboard accessible, screen reader labels, CSP-friendly embed, versioned asset URL. No tenant secrets in embed snippet. Test two domains, two tenants, multiple tabs, invalid locator, disabled bot and expired session.

UX elements to include: welcome message, opening-question chips, typing indicator, source chips for citations, thumbs feedback per answer, scroll-to-bottom, consent-based lead form (see docs/14 §11). The widget is an iframe, not an in-page shadow-root bundle, so unknown client pages cannot reach it.

## Human handoff in the widget (P5)
The widget shows who is answering (AI or a human, with the agent's display name if the bot allows it), a 'talk to a person' button when handoff is enabled, a 'waiting for a person' state, and agent messages within ~3 s via polling `GET /sessions/{id}/messages?since=cursor`. Polling is conditional (H5): the response carries `X-Poll-Hint: active|idle`; the widget polls only while it is `active` (conversation waiting for / with a human, or a follow-up scheduled), takes one look after each turn and when the tab becomes visible again, backs off exponentially (2 s doubling to 30 s) on errors, and never polls in a hidden tab. A handoff seen in a turn resumes polling until the server says `idle`. A pending follow-up is shown on the visitor's next visit. Agent messages are rendered as plain text (no HTML).
